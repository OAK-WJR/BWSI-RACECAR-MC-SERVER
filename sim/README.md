# Race simulator

Players submit Python that drives the racecar; this directory turns that
code into a lap time and a trajectory the server replays.

## Contract

```
python3 simulate.py --code player.py --track track.json --out out.json
```

`out.json` (exit 0 whenever it was written — player mistakes are results,
not failures):

```json
{"status": "ok", "time_s": 42.15, "trajectory": [[x, z, yaw_deg, speed], ...]}
{"status": "error", "error": "off track at t=3.20s"}
```

- Minecraft world coordinates; yaw 0 = +z, yaw 90 = -x.
- Trajectory is sampled at exactly 20 Hz (one point per server tick).
- `track.json` is generated by `scripts/gen_track.py` — do not edit by hand.

## Player API (rc_api.py)

```python
rc.set_speed(speed, steering_angle)   # m/s, degrees; clamped
rc.wait(seconds)                      # hold controls
```

## Swapping in the real simulator

Replace the internals of `simulate.py` (and `rc_api.py` if the API grows)
while keeping the CLI and `out.json` schema. Nothing else in the pipeline
changes. If it needs third-party packages, add a `Dockerfile` here and
point `scripts/race-runner.sh` at the new image.

Security note: player code runs under `exec()` with no Python-level
sandboxing — the Docker container (no network, read-only, resource
limits) is the boundary. Keep it that way.
